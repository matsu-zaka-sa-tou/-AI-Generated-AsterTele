关键设计决策

1. SipTransportContext 共享上下文

internal sealed class SipTransportContext 封装 SIPTransport、AdvertisedEP、LocalEP，由 SipSoftSwitch 持有并传给 Handler，避免全局状态。定义在 ByeHandler.cs 中，由 DI 注册为 Singleton。

2. InviteHandler 工厂注册

InviteHandler 构造函数需要 Func<CallSession, string?, Task> sendByeToCallee 委托（从 ByeHandler 获取），因为 ForwardCalleeResponse 在 200 OK 重传超限时需要向被叫发 BYE。Program.cs 中用工厂模式创建：

services.AddSingleton<InviteHandler>(sp =>
{
    var byeHandler = sp.GetRequiredService<ByeHandler>();
    return new InviteHandler(..., (session, reason) => byeHandler.SendByeToCallee(session, reason));
});

3. CallSession 状态机方法

原 25+ 可变布尔属性无状态机保护，存在竞态风险。新增方法封装状态转换：

  • TryTransitionTo(CallState) — 安全状态转换，校验合法转移
  • MarkCallerHungUp() / MarkCalleeHungUp() — 封装挂断标记
  • MarkCallee200OkProcessed() — 防止重传重复处理
  • ResetCalleeLeg() — 呼叫转移时重置被叫腿

4. internal 类型 + IServiceProvider 解析

InviteHandler/ByeHandler/SipTransportContext 为 internal，不在公共构造函数中暴露。SipSoftSwitch 通过 IServiceProvider.GetRequiredService<T>() 解析，保持 public API 整洁。

RTP 桥接接口设计

IRtpBridge 连接 SIP 信令层与 RTP 媒体流，实现 IVR 语音播放、语音信箱录音等需要 RTP 的功能。

public interface IRtpBridge
{
    // SDP 媒体锚定 (核心: 使 RTP 流经过 AsterTele)
    string? RewriteSdpToCallee(CallSession session, string callerSdp, string calleeSideIp);
    string? RewriteSdpToCaller(CallSession session, string calleeSdp, string callerSideIp);

    // 会话生命周期
    Task OnSessionEstablished(CallSession session, string sdpAnswer);
    Task OnSessionTerminated(CallSession session);

    // 音频功能
    Task PlayPromptAsync(CallSession session, string promptId, CancellationToken ct);
    Task StopPromptAsync(CallSession session);
    Task StartRecordingAsync(CallSession session, string outputPath, int maxDurationSeconds, CancellationToken ct);
    Task<string?> StopRecordingAsync(CallSession session);

    // re-INVITE 媒体修改
    string? GetMediaSdp(CallSession session);
    Task<string?> ModifySessionAsync(CallSession session, string newSdp);

    bool IsMediaAvailable { get; }
}

当前注册 NaudioRtpBridge 实现，已实现媒体锚定。也可替换为其他实现：

  • NaudioRtpBridge — 当前实现，NAudio G.711 编解码 + RTP 双向转发
  • NullRtpBridge — 空实现，纯 SIP 信令模式 (SDP 透传)
  • RtpFfmpegBridge — 使用 ffmpeg 音频编解码 (未来)

RTP 媒体锚定

问题根因

外呼时主叫听不到运营商忙音/提示语。Wireshark 抓包确认：零 RTP 包到达 AsterTele 服务器。原因是 AsterTele 作为纯信令 B2BUA，SDP 透传导致双向 RTP 通路断裂：

  • 运营商发忙音 → 172.48.242.167:24636 (DAG1000 内网端口) → 路由器无此端口转发 → RTP 丢弃
  • 主叫发 RTP → 172.26.160.89:20544 (运营商内网 IP) → 不可路由

解决: RTP 媒体锚定

AsterTele 从纯信令 B2BUA 升级为媒体 B2BUA，每个通话分配两个 UDP 端口做双向 RTP 转发：

修改后的 RTP 流:
  DAG1000 ══RTP══> AsterTele:CallerPort ══转发══> 运营商 RTP 端点
  运营商  ══RTP══> AsterTele:CalleePort ══转发══> DAG1000 的 RTP 端点

NaudioRtpBridge 每个 CallSession 分配:
  - CallerPort: 主叫侧发来的 RTP 入口
  - CalleePort: 被叫侧发来的 RTP 入口
  - 从 RTP 包解码 G.711 → NAudio → WAV 录音
  - 从 WAV 文件 → NAudio 编码 G.711 → RTP 注入 → 播放提示音

SDP 锚定调用点 (InviteHandler.cs 中 5 处)
