1设计思路

1.1 为什么要写 AsterTele

在之前的 Asterisk/PJSIP 实践中，8002 分机注册问题本质上源于 SIP endpoint 匹配模型的设计缺陷。 为了彻底掌控 SIP 信令流程、摆脱黑盒配置的坑，我们决定用 C# 从零实现一个最小可用的 SIP 软交换机。 核心目标：让 Zoiper 能注册、能拨打、能通话。

1.2 技术选型：SIPSorcery

C# 生态中，SIPSorcery（v10.0.12）是目前最成熟的 SIP/RTP 库，提供了完整的 SIP 消息解析、UDP 传输层、Digest 认证和事务管理。我们不需要自己解析 SIP 文本协议， 只需在 SIPSorcery 的 SIPTransport 之上实现业务逻辑即可。

方案：纯 C# 自己写

工作量：需要自己解析 SIP 文本、管理事务、实现 Digest，至少数万行代码。只适合学习，不适合快速交付。

不采用

方案：C# + SIPSorcery

协议栈由库处理，我们专注 REGISTER/INVITE/BYE 的业务逻辑。2000 行代码即可实现可用的软交换。

采用

方案：C# + FreeSWITCH

FreeSWITCH 负责底层，C# 通过 ESL 控制。更稳定但需要额外进程，部署复杂度上升。

备选

方案：C# + Asterisk ARI

类似 FreeSWITCH 方案，仍然依赖 Asterisk 的 PJSIP endpoint 模型，没有解决根本问题。

备选

1.3 核心设计决策

B2BUA 模式而非 Proxy 模式

SIP 代理 (Proxy) 只是转发消息，两端直连后代理不再参与；而 B2BUA (Back-to-Back User Agent) 在服务器两侧分别维护独立的 SIP 对话，可以完全控制信令流程。 B2BUA 的好处：每侧用独立的 Call-ID 和 tag，服务器可以修改 SDP、控制媒体路由、 未来增加 IVR/录音等功能非常方便。

Digest 认证而非 IP 白名单

Zoiper 等 SIP 客户端标准支持 Digest 认证。流程：客户端 REGISTER → 服务器 401 挑战 (携带 nonce) → 客户端用 MD5(username:realm:password) 计算响应 → 服务器验证后 200 OK。 这是 SIP 标准做法，比 IP 白名单更安全。

SDP 透传 + RTP 直连

LAN 场景下，两端可以直接建立 RTP 媒体流，无需服务器中继。 服务器只负责 SIP 信令 (控制面)，RTP (数据面) 在客户端之间直接传输。 这大幅降低了服务器复杂度，也是 Asterisk 的默认行为。

3代码模块详解

3.1 SipOptions.cs — 配置模型

使用 .NET 的 Options 模式，从 appsettings.json 绑定到强类型配置类。 分机列表以数组形式配置，新增分机只需修改 JSON 文件，无需改代码。 

public class SipOptions {
    public string ListenAddress { get; set; } = "0.0.0.0";
    public int    SipPort       { get; set; } = 5060;
    public string Realm         { get; set; } = "asterisk";
    public int    RegisterExpiry{ get; set; } = 3600;
    public List<ExtensionConfig> Extensions { get; set; } = [];
}

public class ExtensionConfig {
    public string Number      { get; set; }  // 分机号，如 "8002"
    public string Password    { get; set; }  // 密码，如 "8002pass"
    public string DisplayName { get; set; }  // 显示名
    public string Context     { get; set; }  // 拨号计划上下文
}

3.2 DigestAuthenticator.cs — SIP Digest 认证

SIP Digest 认证遵循 RFC 2617，是 SIP 世界最主流的注册认证方式。 流程分两步：挑战（服务器发 401 + nonce）和验证（客户端用 MD5 计算响应）。

挑战阶段

Challenge() 方法

收到无 Auth 头的 REGISTER 时，生成随机 nonce，构造 401 响应，在 WWW-Authenticate 头中携带 realm、nonce、qop=auth。

验证阶段

Validate() 方法

客户端携带 Authorization 头重新 REGISTER 后，提取 nonce/username/uri 等字段，用 SIPSorcery 内置的 SIPAuthorisationDigest 重新计算期望值，比对 Response 是否一致。

安全机制：Nonce 一次性使用——验证通过后立即销毁，防止重放攻击。所有 nonce 存储在 HashSet 中，线程安全。

3.3 RegistrationStore.cs — 分机注册存储

使用 ConcurrentDictionary 管理已注册分机，线程安全。 启动时从 SipOptions 加载静态分机配置（号码-密码映射），运行时维护动态注册信息（Contact URI、源地址、过期时间）。

方法作用
ExtensionExists(number)检查分机号是否在配置中
GetExtensionConfig(number)获取分机密码 (用于 Digest 验证)
Register(reg)写入/更新分机注册信息
Unregister(number)注销分机 (expires=0)
GetRegistration(number)查找注册，自动检查过期
CleanupExpired()批量清理过期注册 (定时 60s)

3.4 CallManager.cs — 呼叫会话管理

每一路 B2BUA 通话在服务器两侧各维护一条 SIP 对话腿 (Leg)。 CallSession 记录两条腿的 Call-ID、远端地址、SIP 请求/响应。 三个 ConcurrentDictionary 分别按主叫 Call-ID、被叫 Call-ID、主叫分机号索引，支持双向查找。 

public class CallSession {
    public string  CallerNumber;    // 主叫分机号
    public string  CalleeNumber;    // 被叫分机号
    public SIPRequest  CallerInvite;   // 主叫侧原始 INVITE
    public SIPRequest? CalleeInvite;   // 被叫侧发出的 INVITE (新 Call-ID)
    public SIPEndPoint  CallerRemoteEP; // 主叫远端地址
    public SIPEndPoint  CalleeRemoteEP; // 被叫远端地址
    public CallState   State;           // Initiating / Ringing / Connected / Disconnected
}

3.5 SipSoftSwitch.cs — SIP 软交换核心

这是整个系统的核心，继承 IHostedService，随 .NET Generic Host 启停。 内部使用 SIPSorcery 的 SIPTransport 在 UDP 5060 上收发 SIP 消息， 根据方法类型分发到不同的处理器。

SIP 方法处理器核心逻辑
REGISTER HandleRegister() 提取分机号 → 检查配置存在 → 无 Auth 则 401 挑战 → 有 Auth 则 Digest 验证 → 存储注册 → 200 OK
INVITE HandleInvite() 验证主叫已注册 → 查被叫注册信息 → 100 Trying → 创建 B2BUA INVITE (新 Call-ID/From/Via) → 发给被叫
ACK HandleAck() 匹配主叫 Call-ID → 构造被叫侧 ACK → 转发
BYE HandleBye() 匹配会话 → 200 OK 给发送方 → 向另一方发 BYE → 移除会话
CANCEL HandleCancel() 匹配会话 → 200 OK → 向被叫发 CANCEL → 向主叫发 487
OPTIONS HandleOptions() 直接 200 OK (保活/探测)

3.6 Program.cs — 入口与监控

使用 .NET Generic Host 构建 DI 容器，注册所有服务。 后台启动一个定时任务（每 15 秒），打印当前已注册分机列表和活跃通话，方便运维观察。

4信令流程

4.1 注册流程 (REGISTER)

Zoiper AsterTele | REGISTER sip:asterisk ---------> | 1. 提取 To 头的分机号 | Contact: <sip:8002@ip:port> | 2. 检查分机号是否存在于配置 | | 3. 无 Authorization 头 → 发 401 | 401 Unauthorized <--------- | WWW-Authenticate: Digest realm="asterisk", nonce="abc123" | | | REGISTER (with Auth) ---------> | 4. 取 nonce → 验证 Digest | Authorization: Digest ... | 5. 用 SIPAuthorisationDigest.SetCredentials + GetDigest | | 6. 计算值与客户端 Response 匹配 → 通过 | 200 OK <--------- | 7. 存储注册信息 (Contact/源地址/Expires) | | 8. 返回 200 OK

4.2 呼叫流程 (INVITE)

8001 AsterTele 8002 | INVITE sip:8002 ------> | | 1. 查 8001 已注册 | | | 2. 查 8002 已注册 | 100 Trying <------ | | 3. 回 100 Trying | | INVITE (新CallID) ------> | 4. 构造新 INVITE | | From: 8001, 新Tag | 5. 新 From/To/Via/CallId | | SDP 透传 | 6. Body 原样拷贝 | | 180 Ringing <------ | 7. 被叫振铃 | 180 Ringing <------ | | 8. 转发给主叫 | | 200 OK + SDP <------ | 9. 被叫接听 | 200 OK + SDP <------ | | 10. SDP 透传给主叫 | ACK ------> | ACK ------> | 11. ACK 转发 | <============= RTP 直连 =============> | 12. 媒体流建立 | | BYE <------ | 13. 挂断 | BYE <------ | 200 OK ------> | 14. 转发 BYE | 200 OK ------> | | 15. 双方 200 OK
B2BUA 关键点：INVITE 到被叫时，服务器生成全新的 Call-ID、From tag、Via branch。 两侧的对话完全独立，服务器在中间做翻译。这就是 B2BUA 与 Proxy 的本质区别。

Windows 防火墙：需要放行 UDP 5060 端口（SIP 信令）。 如果使用 RTP 直连模式，两端还需能互相访问对方的 RTP 端口范围（通常 10000-20000 UDP）。 
# PowerShell (管理员) 放行 SIP 端口
New-NetFirewallRule -DisplayName "AsterTele SIP" `
  -Direction Inbound -Protocol UDP -LocalPort 5060 -Action Allow

6.3 拨打电话

  1. 确保 8001 和 8002 都已在 Zoiper 注册成功
  2. 在 8001 的 Zoiper 上拨号 8002
  3. 8002 的 Zoiper 应振铃
  4. 接听后，RTP 媒体流在两端直连
  5. 挂断后，BYE 信令经 AsterTele 转发，会话清除
常见问题：
1. Zoiper 显示 "Registration failed" → 检查 IP/端口/密码是否匹配，防火墙是否放行 UDP 5060
2. 注册成功但无法通话 → 检查两端能否互相访问 RTP 端口 (10000-20000 UDP)
3. 一方听不到声音 → SDP 中 RTP 地址可能不可达，LAN 场景下确保两端在同一子网

7扩展方向

RTP 中继

当前媒体直连。若需 NAT 穿透或录音，可在服务器上启动 RTP Session 做媒体中继，两端 RTP 发给服务器而非互发。

SIPSorcery 原生支持

编解码协商

当前直接透传 SDP。可增加 SDP 解析与重写，在 B2BUA 层做 codec 协商 (G.711/G.722/OPUS)。

需扩展 SipSoftSwitch

IVR 语音菜单

被叫端播放提示音、收集 DTMF 按键，实现类似 Asterisk dialplan 的交互式语音应答。

需 RTP 中继 + 音频播放

IMS 对接

中国电信 IMS 需要 SIP over TCP/TLS + 特定 Header。可增加 TCP 通道和 IMS 适配层。

需 SIPTransport 加 TCP Channel

Web 管理后台

ASP.NET Minimal API 暴露 REST 接口：查看注册/通话状态、动态添加分机、强拆通话等。

轻量扩展

数据库持久化

将分机配置从 JSON 迁移到 MySQL，注册信息持久化，重启不丢失。

标准 Entity Framework
